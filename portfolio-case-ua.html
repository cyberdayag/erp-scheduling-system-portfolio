Контекст і проблема

Почавши працювати в науково-освітньому центрі фізики та хімії, я виявив, що організація працює на важкій системі, побудованій на базі Excel. Вона постійно падала, зависала під навантаженням і робила щоденні операційні зміни вкрай болісними та схильними до помилок.

Масштаб операційного навантаження:
26 шкіл-партнерів до 50 уроків на день 105 навчальних груп спеціалізовані лабораторії часті заміни викладачів, скасування та перенесення уроків замовлення обладнання

Досвід роботи з транзакційними системами сформував простий принцип: будь-яка зміна розкладу чи ресурсів має оброблятися так само суворо, як банківська операція. Тому я спроєктував систему, що гарантує цілісність на рівні СУБД, незмінний Audit Log і можливість безпечного відкату (rollback) будь-якого дня.

Моя роль

Вивчивши бізнес-процеси центру, я самостійно спроєктував архітектуру системи: модель даних, ключові бізнес-інваріанти, рольову модель доступу, механізми розв'язання конфліктів. Також спроєктував схему деплою (AWS EC2 + Cloudflare Tunnel) та процес резервного копіювання (AWS S3) з перевіреним відновленням після повного збою.

З AI я працював як техлід із командою розробників: ставив завдання, визначав рішення кожного з них, покроково перевіряв код на кожному етапі, перш ніж прийняти його в систему.

Повноцінна ERP-платформа для управління розкладом та операційною діяльністю:

  • Річний шаблон + згенерований на його основі розклад на рік
  • Редагування розкладу на рівні дня з freeze / unfreeze / rollback
  • Заміни викладачів
  • Скасування та перенесення уроків
  • Створення нових уроків і додаткових занять
  • Процес замовлення лабораторного обладнання
  • Черга заявок (принцип «одного вікна»)
  • Гранулярний рольовий доступ
  • Коридорні ТВ-табло для викладачів і учнів
  • Повністю незмінний audit log

Технологічний стек:

PostgreSQL 16 PL/pgSQL Node.js + Express Vue 3 + PrimeVue (RTL) Docker · AWS · Cloudflare Tunnel
  • PostgreSQL — обрано заради нативної підтримки EXCLUDE USING GIST. Це дозволяє на рівні движка СУБД гарантувати відсутність перетинів часових інтервалів і автоматично виключати race conditions за паралельних запитів.
  • Логіка в БД — перенесення інваріантів у СУБД забезпечило єдине джерело правди і цілісність даних незалежно від точки підключення (API, фонові скрипти чи прямі адмін-сесії).
  • Node.js + Express — тонкий stateless-шлюз (Thin API Gateway), обмежений завданнями авторизації та транзиту запитів без дублювання бізнес-логіки.
  • Vue 3 + PrimeVue — скоротив time-to-market завдяки готовій екосистемі складних UI-компонентів для адміністративних екранів.
  • Cloudflare Tunnel — ізолював інфраструктуру за принципом Zero Trust, повністю виключивши потребу публікації публічного IP та відкриття вхідних портів.

Інтерфейс системи

Натисніть на будь-який скриншот, щоб відкрити його у повному розмірі.

Денний Гантт — актуальний розклад дня по кабінетах. Кольорове кодування предметів, підсвітка замін, індикатор поточного часу.
Річний шаблон (Basic Schedule) — джерело правди. Зміни з нього безпечно поширюються на згенерований річний розклад за допомогою двофазного алгоритму.
Дашборд викладача — особистий кабінет: найближчі уроки, заявки на обладнання, історія замін та робочий графік.
Адмін-дашборд — центральне «одне вікно». Викладачі лише створюють заявки, адміністратори розглядають, коригують і застосовують зміни.
Дашборд лаборантів — операційна вітрина: замовлення обладнання та нотатки на обраний день.
Audit Log — повністю незмінна історія всіх значущих дій. Навіть суперадмін не може змінити чи видалити записи.
Табло для учнів — публічний екран з поточним розкладом.

Інженерна культура — код і документація

Один із ключових принципів проєкту: логіка і рішення пояснюються прямо в коді — не лише що робить функція, а й навіщо вона потрібна і що зламається, якщо порушити інваріант.

1. Чіткий поділ структури та бізнес-логіки

schema.sql — явне правило: тут лише структура. Бізнес-логіка живе в модульних файлах.

2. Підбір кабінетів із явними бізнес-правилами

campus._find_room() — правила пріоритету кабінетів для фізики та хімії задокументовані й закодовані прямо в запиті.
year_schedule.sql — у шапці файлу пояснюється призначення кожної ключової функції та потік freeze / unfreeze дня.
